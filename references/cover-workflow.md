# 封面、封底与可重新编译的 PDF

仅在用户要求制作、修改或接入封面/封底时使用。沿用现有多文件 TeX 工程和构建环境；通用翻译与验收仍见主 skill 及 project-workflow.md。本流程不授权重画原书实验图、修改正文或自动安装 TeX 发行版。

## 可选版式示例

以下是一组可选搭配，须由用户在当次任务中选择；用户明确要求其他版式时遵循该要求，不自动套用于所有书籍：

- 正封上部约 60% 为与书籍科学主题相符的主题画；中间有一条颜色与画面协调的横向分隔线；下部约 40% 为白底文字区。
- 白底区放准确的中文书名、英文书名和作者，留足安全边距。不出现“中文译稿”等未经要求的版本标签。
- 封底示例为与前封面不同构图的全幅纯插画，科学主题和色系协调；整页没有任何文字，也没有白底文字区或分隔横线，不复制前封面构图。

封底规格独立按用户当次要求确定；上述全幅无文字规格仅在用户选择时采用。前封面的 60/40 分区与文字要求不自动延伸到封底。

先从原 PDF 扉页、版权页、项目记录及用户明确说明交叉核对书名和作者的拼写、顺序与中文译名；有冲突时保留已知信息并查明，不能把生成图中的文字当作书目信息来源。没有确认的中文译名不得伪装成已确认译名。

字体遵循 [typography.md](typography.md) 及工程的已冻结方案。需要精确统一封面字体时，图像生成只制作主题画，书名和作者由共享字体在 TeX 或确定性排版工具中绘制；不要把生成图中的“宋体风格”认作精确字体证明。用户明确要求整张封面由图像工具生成时，按其要求核对并记录为视觉近似。下面生成提示词的文字要求仅适用于含生成文字的模式；纯画模式的文字在排版阶段核对。

## 图像生成与参考图分工

默认使用可调用的内置 `imagegen`，不要求用户提供 API 密钥。读取其当前技能/工具说明；若内置能力不可用，报告能力边界，不以安装外部工具或索要密钥作为默认替代。编辑本地图前先实际查看图片；使用用户参考图时也先查看，不能只凭文件名推断内容。

给每张参考图明确角色：用户布局模板用于分区、留白和文字位置；旧封面或书籍材料用于科学主题、配色或内容背景。保留书籍科学主题，不把布局模板上无关的主题、作者或文字带进成品。生成的封面主题画用于装饰，不作为真实实验数据、物理结果或精确科学示意的证据。

前封面布局参考经验：仅引用用户布局模板更容易保留所需分区，同时在提示词中明确书籍主题；把旧封面也作为图像参考，常会锁定旧封面原有的分界。遇到分区反复偏离时，可改为只引用布局模板，并用文字重述主题和准确书目信息。这是针对该失败模式的优先尝试，不保证所有生成任务都如此。用户选择上述全幅封底示例时，不沿用前封面分区模板；参考前封面时仅取科学主题和配色，明确要求不同构图、画面铺满整页、无文字/白底文字区/横线。

提示词按所选版式明确画幅、构图、全部准确文字和边距。采用上述前封面示例时，明确画面上部/白底下部的目标比例和分隔线。仅写“60/40”不能保证像素位置：实际查看每次成图，核对分隔线相对总高度的位置、白底区域、主题和字形，特别检查中文漏字/错字、英文及作者拼写。封底另写当前规格；采用上述封底示例时，须视觉核对其为不同构图的全幅纯插画，检查是否误带任何文字、白底文字区或分隔横线。视觉核对失败时，针对布局或文字问题修改提示词重新生成；不要把未核对的版本当作最终资产。保留最终选择和采用理由。

## 工程资产与记录

把验收后的图片保存到工程内，例如 `translation/covers/front-cover.png`、`translation/covers/back-cover.png`，不要只留在 `.codex` 生成目录。保留原始生成文件及已采用资产之间的来源关系；不要覆盖原书图片。封面/封底单独存放，不混入原 Mathpix 书图及其物理尺寸映射；按工程实际原图清单核验。

在现有 `project.json` 中增加封面记录，保留已有字段。可用 `covers.front`、`covers.back` 表达下列信息；路径相对工程根目录，字段名称可适配已有约定：

| 字段 | 记录内容 |
| --- | --- |
| `asset`, `sha256` | 工程内最终图片路径、文件 SHA256 |
| `prompt`, `generator` | 实际采用的完整提示词、内置生成工具及生成时间/标识（可获得时） |
| `references` | 各来源的路径或来源标识、可计算的哈希、角色（布局模板/科学主题/配色等） |
| `title_zh`, `title_en`, `author`, `bibliographic_source` | 含文字资产中实际核对后的文字及其依据；无文字资产按所选规格记录为无文字 |
| `layout` | 前封面和封底各自的当前用户要求、分区或全幅构图、文字及分隔线有无、实际视觉核验结果；不是只抄提示词 |
| `fit` | PDF 放置方式、页面尺寸、等比缩放、居中方式、安全空白裁切范围及核验 |
| `tex_entry`, `qa` | 接入位置、构建/渲染证据、首末页检查、正文比较结果与范围 |

提示词较长时可存工程内的文本文件，并在 `project.json` 中记录路径与 SHA256；同样保存来源角色和最终资产哈希。仅填写已知值，未知的生成标识或来源信息明确记为不可获得，不编造。

## 接入现有 TeX 工程

修改可重编译的源工程，不只给成品 PDF 外部拼接图片。先查看入口、原扉页/封面生成位置、页面尺寸、页码控制和书签。首选用新封面替换已有扉页，避免新封面后又出现一个旧封面；保留必要的版权页和正文。若工程没有可替换页面或用户明确要求另加扉页，按该实际情况处理并记录对分页的影响。封底放在末页，且不会让正文浮动图表被吞掉或挪入封底。

为封面页使用独立放置逻辑：无页眉、页脚或页码；等比缩放，居中铺满目标纸张。先核验图片与纸张宽高比；只允许裁切已确认安全的空白，不拉伸文字、不截断标题、作者或主题。若铺满需要裁掉有效内容，应调整资产画幅/留白或重新生成后再核验，不以强制宽高缩放掩盖比例不符。

有 Mathpix 图片物理尺寸映射或全局 `includegraphics` 包装时，封面必须绕开该书图映射：使用工程已有的原始 graphicx 命令别名，或在映射重定义前保存专用于封面的原始命令。不要关闭或改写正文图片映射来容纳封面。保持原书图片文件、路径和绘制尺寸不变。

保持正文页码、目录、交叉引用和书签目的页；封面局部页面样式/尺寸设置不能泄漏到正文。沿用现有构建命令并重新编译到引用收敛，检查缺字、引用、图片和布局日志。没有实际执行不得记录编译通过。

编译收敛经验：旧 PDF 被查看软件锁定时，可改用新 job 名输出；若新 job 没有既有的 aux/toc 文件，两遍编译后，多页目录仍可能保留首次尚未生成完整目录时的过渡页码。即使其他正文页已与旧版像素、提取文字相同，日志也可能未明确提示目录问题。继续编译可使页码收敛。因此应对照目录实际条目页码与正文目标页，并检查 aux/toc 等辅助文件在连续编译后是否稳定；按工程实测收敛确定编译遍数，不能仅凭固定遍数结束或没有警告宣称目录正确。

## PDF 核验与交付

保留修改前的 PDF 及其哈希作为比较基线。实际渲染最终 PDF 的首、末页，按前封面与封底各自规格核对构图、文字、边距、等比放置和页眉页脚，确认新封面仅出现一次且封底确为最后一页。采用上述示例时，首面检查 60/40 分区、横线及准确书名作者；末页检查与首面不同的全幅插画，且无任何文字、白底文字区或分隔横线。生成图片看起来正确，并不能证明它在 PDF 中放置正确。

核对目录、页码和书签，按页面内容对齐修改前后的正文页面。若报告“正文不变”，须有实际证据：以相同渲染参数比较所有对齐正文页的像素，同时比较实际提取的正文文字，记录页数、比较范围和差异。PDF 文件整体哈希变化或页数相同都不能证明正文不变；只检查少量页面只能报告抽查范围。若出现差异，查明是渲染、文字提取、分页还是内容变化，修复或明确报告，不能将未解释差异记为通过。

更新项目的实际构建结果与核验记录，再重新打包可重编译工程。压缩包包含 TeX、最终封面/封底图片、仍需的原书图、字体/构建说明及项目记录，并包含采用的 skill 副本（含本参考）。以包内工程的相对路径可定位资产为准，检查封面文件存在且 SHA256 与记录一致。交付 PDF 和工程包，简要说明封面替换、封底追加、采用版式及正文核验的实际证据与剩余限制。
